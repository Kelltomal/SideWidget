# Пульт SideWidget на Android через домашний Wi-Fi

Статус: схема одобрена пользователем 5 ноября 2026; реализация ведётся по отдельному плану. Поздние прямые дополнения пользователя: установка из Chrome как приложение и независимость от VPN. Поэтому HTTP-only транспорт ниже заменён на HTTPS с локальным CA/ручным доверием Android; HTTP остаётся только для setup. Пульт привязан к выбранному домашнему адаптеру, VPN с запретом LAN требует Allow LAN. Актуальное поведение и приёмка — [PHONE_REMOTE](../../PHONE_REMOTE.md).

## Задача и согласованные решения

Пользователь слушает Яндекс Музыку на ПК. Телефон должен управлять воспроизведением через страницу SideWidget в браузере. Пользователь выбрал Wi-Fi вместо отдельного Android-приложения с Bluetooth. После первого подключения телефон запоминается; после запуска ПК и восстановления домашней сети повторное разрешение не требуется.

## Подходы

1. **Локальная страница, которую обслуживает SideWidget — выбран пользователем.** Использует существующие C#/WinUI/React и Windows-медиасессии. Не требует Android-приложения или внешнего сервера. Браузер нужно открыть самому; доступность зависит от домашней сети и адреса ПК.
2. Отдельное Android-приложение. Позволило бы добавить Bluetooth и фоновое обнаружение, но требует отдельной установки, поддержки и разрешений Android. Не входит в выбранный вариант.
3. Внешний сервер или туннель. Даёт стабильный интернет-адрес, но добавляет внешнюю зависимость и удалённый доступ, которых пользователь не просил. Не выбран.

## Пользовательский сценарий

В музыкальном блоке SideWidget появляется действие «Пульт на телефоне». Открывается настройка: включить пульт, адрес и QR, автозапуск вместе с Windows, список допущенных телефонов, отключение и отзыв доступа.

При первом включении пульта предлагается включённый переключатель автозапуска. Настройка применяется явным действием включения. Автозапуск действует для текущего пользователя после входа в Windows, запускает компактный SideWidget без захвата фокуса. Отдельная системная служба не устанавливается. Выключение автозапуска удаляет только запись SideWidget.

Пользователь сканирует QR штатной камерой телефона. На ПК подтверждает новый пульт по совпадающему коду. После подтверждения телефон получает постоянный ключ доступа. Следующие открытия страницы не требуют QR или нового подтверждения. В браузере можно сохранить закладку или обычный ярлык страницы; установка PWA и фоновое исполнение не обещаются.

Открытая страница повторяет соединение после перезапуска SideWidget, сна ПК и потери Wi-Fi. Возврат во вкладку немедленно обновляет состояние. Android может приостановить скрытую вкладку; восстановление происходит при её открытии. Автоматический запуск браузера на телефоне, включение ПК и запуск музыки без команды не входят в функцию.

## Экран телефона

Отдельная мобильная поверхность в существующем стиле SideWidget: Medeo, действующие светлая и тёмная палитры, спокойные поверхности, реальные обложки. Режим Operate. Без перестройки существующей шторки.

Сверху — SideWidget и состояние подключения. Далее выбор медиасессии при нескольких источниках, обложка, название и исполнитель, время и перемотка при поддержке, крупные кнопки предыдущего трека, воспроизведения/паузы и следующего трека. Ниже — явно подписанная «Громкость ПК» и отключение звука. Это общая громкость текущего устройства вывода, не обещание отдельного регулятора Яндекс Музыки.

Размеры интерактивных областей не меньше 48 CSS px. Названия переносятся; длинный трек не сдвигает кнопки за экран. Проверка на ширинах 360, 412 и 768 px, в обеих темах, с увеличенным текстом и клавиатурой. Без декоративной анимации и постоянной визуализации звука на телефоне.

Состояния: ожидание подтверждения, отказ/истечение QR, соединение, нет связи, ПК снова доступен, нет медиасессий, команда не поддерживается, источник завершён, доступ отозван. При потере связи старый трек отмечается как устаревший, команды отключаются. Не показывать ошибку отправленной команды как успех; автоматически не повторять предыдущий/следующий трек после неизвестного результата.

Пульт управляет источниками, видимыми Windows. Сначала выбирается воспроизводящая сессия, затем запоминается выбранный источник в пределах живой сессии. Исчезновение выбранного источника не должно незаметно направлять уже отправленную команду другому плееру. Яндекс Музыка в приложении и браузере требует живой проверки; кнопки доступны только по capabilities существующего MediaService. Поиск каталога, плейлисты, лайки и API аккаунта Яндекса не входят в первую версию.

## Архитектура

- Отдельный ограниченный HTTP-хост Kestrel внутри SideWidget.App, на существующем .NET 10. Self-contained публикация должна включать требуемый ASP.NET Core runtime; системная установка runtime не нужна. Добавление framework reference и размер portable-сборки проверяются при реализации.
- Отдельная точка входа React/TypeScript для пульта; сборка Vite публикует её вместе с приложением. HTTP-хост отдаёт только явно разрешённые файлы пульта, его шрифты и assets. База, профиль, desktop HTML и общий WebView2-мост не публикуются.
- MediaService и AudioService остаются единственными исполнителями. Для сети выделяется узкий фасад: состояние музыки, media-команды, общая громкость и mute выхода. Запросы медиасервиса направляются через WinUI dispatcher и сериализуются с существующей шторкой; HTTP-потоки не вызывают общий Controller.Handle и не подделывают доверенный origin WebView2.
- Отдельные настройки пульта и парных устройств, с версией формата и атомарной записью, без изменения старых пользовательских данных. Сервер хранит хеши случайных ключей телефонов, имена/время последнего использования и ID; браузер хранит свой ключ для текущего origin. Ключи и приглашения не попадают в логи.
- HTTP API: первичное приглашение и подтверждение, проверка состояния подключения, снимок музыки/общей громкости, узкие POST-команды. Опрос активного экрана примерно раз в секунду, без аудиопотока. После сбоев — ограниченная задержка повторов до 10 секунд, немедленный повтор при online/visibilitychange. Обложка кэшируется по треку и не передаётся заново каждую секунду.

## Сеть и автоматическое восстановление

Работает в одной домашней локальной сети: телефон по Wi-Fi, ПК по Wi-Fi или Ethernet. Гостевая сеть с изоляцией клиентов может блокировать доступ. Сервер запускается только после включения функции и только на адресах разрешённых домашних интерфейсов; публичные, туннельные и VPN-интерфейсы не выбираются автоматически. Подписка на изменения сети пересобирает адреса и listener после сна/подключения сети; повторная подписка не создаёт второй сервер.

Порт постоянный и сохраняемый. Если занят, показать понятную ошибку и предложить изменить его; не менять адрес молча при каждом запуске. В настройках виден фактический доступный адрес, состояние listener и подсказка по Windows Firewall. Исключение требуется только для частной домашней сети; не отключать firewall и не открывать публичные профили. Возможный системный запрос разрешения не считать автоматически пройденным. Если права требуются для правила, приложение сохраняет работоспособность без повышения прав и объясняет ручную настройку.

Первый надёжный адрес — локальный IPv4 ПК. Автоподключение после перезапуска проверяется при сохранении адреса и порта. При смене DHCP-адреса страница по старому IP недоступна: показать новый QR в SideWidget; для постоянной домашней закладки рекомендовать закрепить адрес ПК в DHCP роутера. Произвольное сканирование подсети браузером и гарантированное .local-обнаружение на неизвестном Android не входят в обещание первой версии. Этот предел нужно показать до включения автоподключения, а не скрывать в отчёте.

## Граница доступа

Домашний HTTP без облака и без установки сертификата на Android. Он не шифрует содержимое внутри LAN; это осознанная граница первой версии, отражённая кратко в настройке. Не заявлять защиту от перехвата или подмены трафика недоверенным участником домашней сети.

QR содержит одноразовое криптографическое приглашение во fragment, срок до пяти минут. Оно не даёт права на музыку до явного подтверждения на ПК. Приглашение после использования/отказа/истечения становится недействительным; получение ключа после подтверждения ограничено конкретной попыткой. Долгоживущий ключ не помещается в URL. Изменения требуют авторизации, JSON, отдельного заголовка и проверки точного Origin/Host. CORS не разрешается сторонним сайтам; Host сверяется с реально разрешёнными адресами, чтобы не принимать DNS rebinding. GET ничего не переключает.

Ограничить число телефонов, ожидающих подтверждений, одновременных запросов, размеры тела, частоту опроса и команд. Ограничивать входящие адреса локальными подсетями выбранных интерфейсов. Проверять структуру, диапазон громкости, capability и актуальность session ID. Ручки микрофона, файлов, поиска, буфера обмена, запуска приложений, системных действий, перевода и SellyBoard недоступны по сети. Отключение пульта останавливает listener; отзыв телефона немедленно аннулирует его ключ. Закрытие приложения отменяет запросы и освобождает порт.

## Проверки и критерии готовности

1. Модульные проверки приглашений/истечения/отзыва/сохранения доверия и строгого allowlist команд. Негативные HTTP-проверки Origin/Host, отсутствующего ключа, лишних полей, лимитов и закрытых маршрутов.
2. Интеграционная проверка живого локального HTTP-хоста с подставным медиасервисом: подключение, подтверждение, управление, отзыв, остановка/повторный запуск на том же порту. Проверка упаковки portable.
3. UI-проверки мобильных размеров, тем, длинного трека, неподдерживаемых кнопок, потери связи и повторного подключения. Рендер осматривается в браузере; выполнить глобальные Impeccable-проверки, не дублировать hooks в проекте.
4. Windows-проверка реальной Яндекс Музыки: название/обложка, пауза/возобновление, предыдущий/следующий, перемотка если поддерживается, общая громкость. Реальные переключения выполнять ограниченно и явно учитывать их в отчёте.
5. Приёмка с физического Android в домашней сети: первый QR, запоминание после повторного открытия браузера, восстановление после перезапуска SideWidget и сна ПК. Включение ПК и вход в Windows проверяют автозапуск отдельно. Если физический телефон недоступен инструментам, не объявлять эту проверку пройденной; дать пользователю готовую сборку и короткие шаги приёмки.

## Решения исполнителя и оставшиеся ограничения

Выбор Kestrel, HTTP для доверенной LAN, общая громкость выхода, локальный IPv4 с DHCP-оговоркой и опрос вместо WebSocket — предложения исполнителя. Пользователь выбрал браузер/Wi-Fi, но эти технические детали ещё не согласованы. Конкретный порт, схема файлов, значения ограничений и детали компонентов остаются исполнителю при соблюдении описанного поведения.
