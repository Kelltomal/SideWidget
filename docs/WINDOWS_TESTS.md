# Проверки Windows

Из корня репозитория, Windows x64 и .NET SDK из `global.json`:

```powershell
./scripts/test-windows.ps1
```

Скрипт использует `.tools/dotnet/dotnet.exe`, при его отсутствии — `dotnet` из PATH. Проект запускается через .NET без отдельного apphost; WinUI и WebView2 для harness не нужны. Первая сборка может скачать зависимости SDK через NuGet. Для повторного запуска без restore добавьте `-NoRestore`; конфигурация выбирается через `-Configuration Release`.

По умолчанию проверки только читают состояние Windows: CPU/RAM/диски/сеть, Core Audio, GSMTC и обложки, индекс существующего Everything, connectivity Windows. Проверяются ограничения данных, неизменность ID между опросами, разделение ответов Everything и отклонение неверных адресов. Имена приложений/треков/устройств, идентификаторы и пути в вывод не попадают. Результаты — PASS/FAIL/SKIP и счётчики. FAIL даёт ненулевой код выхода; SKIP означает непроверенную доступность, а не успех функции.

Everything не запускается и не перенастраивается. Если обычный пользовательский экземпляр недоступен, IPC-проверка явно пропускается. Отсутствующий медиаплеер или устройство тоже не создаются ради теста.

Публичные сетевые проверки включаются отдельно:

```powershell
./scripts/test-windows.ps1 -PublicOnline
# Или напрямую:
./.tools/dotnet/dotnet.exe run --project tests/SideWidget.Windows.Tests -- --public-online
```

Этот режим отправляет HTTPS HEAD на `yandex.ru` и ICMP echo к `cloudflare.com`, включая необходимый DNS. Проверяются таймаут, разделение HTTPS/ICMP и запрет одновременных/слишком частых запросов. Нет тела HTTP-ответа, cookies, переходов по redirect, определения местоположения или получения внешнего IP. Недоступность публичной цели отмечается SKIP; корректный ограниченный ответ об ошибке проверяется отдельно от доступности интернета.

Harness не вызывает воспроизведение, смену громкости/mute, запуск файлов, переключение устройств, picker, глобальные hooks, системные настройки или команды питания. `ScreenPicker.cs` только компилируется. Интерактивные сценарии выбора/отмены, реальные команды медиаплеера, смена устройств и несколько мониторов требуют отдельной ручной проверки в приложении. Успешный harness не доказывает работоспособность этих сценариев.
