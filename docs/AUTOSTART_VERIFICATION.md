# Автозапуск — 5 ноября 2026

В настройках добавлен раздел «Автозапуск» с переключателем «Запускать при входе в Windows». Применение немедленное через `startup.get` / `startup.set`. Источник состояния — Windows, отдельная копия в SQLite не создаётся. Используется запись SideWidget в HKCU Run с кавычками вокруг полного пути EXE. Права администратора не нужны. Настройка сама не включается.

Windows StartupApproved учитывается: при внешней блокировке показывается подсказка. Отказ чтения оставляет переключатель недоступным с повтором; отказ записи сохраняет прежнее отображённое состояние.

Проверено:

- 15 веб-тестов автозапуска и существующих сценариев настроек прошли.
- 8 нативных Windows-проверок прошли; публичные сетевые проверки пропущены по умолчанию. Тест автозапуска использует уникальную тестовую ветку реестра, удаляемую после выполнения, и не изменяет реальную автозагрузку.
- Основной C# harness: 1004 проверки плюс проверки хранилища, приложений и сетевых сервисов прошли.
- Веб-сборка и native publish прошли. Результат: `artifacts/autostart/SideWidget.App.exe`.
- Просмотрены браузерные снимки настроек 360 × 620 и 444 × 620: `output/playwright/autostart-settings-*.png`. В браузере переключатель честно недоступен.
- Ручной Impeccable detector для main.tsx и StartupSettings.tsx: пустой список находок. Автоматические сообщения hook также получены.

Общий веб-прогон во время параллельных изменений звука: 171 из 172 прошли; упал `volume-sync.test.tsx > does not let a delayed audio.set reply overwrite a newer Windows value`. Предыдущий прогон также обнаружил нестабильность теста clipboard в music.test.tsx. Эти результаты не являются подтверждением полной зелёной проверки звукового модуля.

Текущий работающий экземпляр из `artifacts/compact-strip-pass-through` не заменялся. Выход из Windows и повторный вход не выполнялись. Для новой версии закрыть прежний экземпляр через трей и запустить собранный EXE.
