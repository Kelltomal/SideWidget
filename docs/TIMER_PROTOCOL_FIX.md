# Исправление отмены таймера — 0.3.5

При паузе, продолжении, удалении и остановке сигнала веб-интерфейс передаёт
ID выбранного отсчёта. Протокол ошибочно разрешал этим командам только
пустой набор параметров. Проверка отклоняла команду ещё до присваивания
переменной обработчика, поэтому ответ об ошибке не отправлялся. Таймер
оставался активен, а кнопки блокировались до трёхминутного таймаута моста.
Сворачивание не устраняло это состояние.

Теперь timer.pause/resume/reset/dismiss принимают необязательный id.
Вызовы без id из нативной шапки по-прежнему работают с главным отсчётом.
Отклонение параметров доверенного, корректного сообщения сохраняет
requestId: интерфейс сразу получает ошибку и снимает блокировку кнопок.
Недоверенным источникам коррелированный ответ не отправляется.

Проверки:

- До исправления: настоящий WinUI/WebView2, timer.reset с id не получает
  ответа, timer.reset без id работает; новый тест падает «Неизвестный параметр».
- После исправления: тесты ядра и протокола проходят, 30 проверок мониторов
  проходят; Windows-приложение собирается без предупреждений.
- scripts/test-native-timer.mjs проходит на отдельном тестовом профиле:
  старт свёрнутым, выборочная пауза/продолжение/удаление, завершение и
  остановка сигнала, немедленный ответ на неверный параметр, раскрытие панели.
- Проверка выполнялась через настоящий локальный WebView2-мост. Команды
  выключения/перезагрузки не запускались. Пользовательские таймеры и профиль
  не затрагивались.
