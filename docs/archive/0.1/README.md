# SideWidget 0.1 — локальный рабочий релиз

Нативная панель Windows 11: C# / WinUI 3, локальный React в WebView2 и отдельные Python-процессы. Панель закреплена у верхнего края выбранного монитора; одна шапка, раскрытие вниз, ширина 444 DIP по умолчанию. Medeo Sans и Medeo Mono включены в пакет, сетевой загрузки шрифта нет.

## Запуск готовой сборки

Запустите `artifacts\release\SideWidget.App.exe` либо из корня проекта:

```powershell
./scripts/run.ps1
```

Для готовой сборки не нужны Node.js, системный Python или установленный .NET. Нужен **Microsoft Edge WebView2 Runtime**; он найден на проверенном компьютере. Если Runtime отсутствует, приложение показывает инструкцию, ничего не устанавливает автоматически. Официальная загрузка: https://developer.microsoft.com/microsoft-edge/webview2/#download-section

Наведение раскрывает панель. Клик включает ввод. `Ctrl+Alt+Space` открывает/сворачивает; `Escape` сворачивает. Кнопка закрепления удерживает окно. Настройки позволяют выбрать `Ctrl+Shift+F12`, размеры, монитор, задержку, порядок карточек и фоновое обновление. Правый клик по значку в трее — выход.

## Что работает

- Сохранённые GET/POST/PUT/PATCH/DELETE с нативной проверкой origin и подтверждением записей; JSON и multipart с выбранными файлами. Профили хранят только ссылку на DPAPI-секрет. Поддержана Bearer-авторизация.
- Поле JSON по пути `data.items.0.value`, ожидаемое значение, периодические GET от 30 секунд, условное предупреждение по равенству. В фоне расписание выключено по умолчанию.
- HTTP-статус, время ответа, давность данных, ошибки сети и ограничений; POST автоматически не повторяется. После отмены отправленной записи результат обозначается как неподтверждённый.
- Изображения 1500×2000, contain или центральный crop, без перезаписи оригинала. Прогресс, отмена, PNG-предпросмотр и папка результатов.
- Две CSV-выгрузки UTF-8 с `sku,quantity`: отчёт расхождений, отдельное обозначение отсутствующего значения, запрет дублирующихся SKU.
- Шаблон `{{name}}` / `{{sku}}` с обязательными переменными и выделяемым результатом. Автоматической отправки нет.
- SQLite-настройки, журнал последних операций, безопасный экспорт геометрии и раскладки. Пример декларативного виджета — `widgets/local-health.json`.

SellyBoard и GitLab показывают «Не настроено»: специализированные адаптеры и production-доступы не подключены. Все 40 функций и оставшиеся ограничения перечислены в `docs/FEATURE_MATRIX.md`.

## Локальный тестовый API

В отдельном PowerShell из корня проекта:

```powershell
./.venv/Scripts/python.exe tests/fake_service.py
```

Нажмите «Проверить» в карточке сервера: GET `http://127.0.0.1:18741/health`. В API-действиях отправьте тестовый POST: после нативного подтверждения `/echo` вернёт реально полученное JSON-тело. Fixture слушает только loopback. Завершение — `Ctrl+C` в его консоли. Ничего не отправляется на реальные сервисы.

## Воспроизводимая разработка

Требования для сборки: Windows x64, Node.js 24, Python 3.13 для создания `.venv`, интернет для первоначального восстановления пакетов. Системные настройки и политики безопасности менять не нужно.

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1
./scripts/test.ps1
```

`bootstrap.ps1` явно загружает проверенный SHA512 архив .NET SDK 10.0.403 в `.tools`, создаёт `.venv`, устанавливает зафиксированные dev-зависимости с хешами. `build.ps1` собирает веб-часть, self-contained WinUI/.NET и включает Python 3.13.14 embeddable с Pillow 12.0.0. Python-архив проверяется по SHA256. `pip` нужен при сборке, но отсутствует в запускном пути приложения.

`test.ps1` поднимает собственный fixture, запускает C# unit/integration, pytest, Vitest и TypeScript build; завершает только созданный им fixture. Перед тестами освободите порт 18741. GitLab CI использует runner с тегами `windows,x64`; Linux runner не заменяет нативную проверку.

## Данные и поставка

Для переносимого архива после сборки выполните `./scripts/package.ps1`. Результат — `artifacts/SideWidget-0.1.0-win-x64.zip` и файл SHA256 рядом. Распакуйте архив целиком и запустите `SideWidget.App.exe` из распакованной папки.

Данные находятся в `%LOCALAPPDATA%\SideWidget`: SQLite, DPAPI-файлы `secrets`, WebView2-профиль и `artifacts`. Журнал ограничен 1000 записями / 30 днями; SQLite — 4096 страниц. Артефакты автоматически не удаляются. Экспорт настроек не переносит секреты, профили, запросы, ответы или файлы.

Поставка — распакованная папка x64; переносить нужно всю папку `release`, а не только EXE. Подписанного установщика, MSIX и автообновления пока нет. Windows App SDK и .NET включены self-contained; WebView2 остаётся внешним Evergreen Runtime. Работа не требует администратора.

Проверки и реальные ограничения: `docs/TEST_REPORT.md`, `docs/SECURITY.md`, `docs/NEXT_STEPS.md`. Исходное ТЗ сохранено в `docs/SPEC.md`.
